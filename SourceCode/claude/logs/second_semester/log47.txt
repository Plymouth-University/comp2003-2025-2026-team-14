  private void OnPlayerLeft(string playerId)
  {
      Debug.Log($"LobbyUIManager: Player left {playerId}");
      UpdatePlayerListUI();
      UpdateButtonInteractability();

      // If the player that left is the local player, we've been kicked or 
  disconnected
      // Clean up multiplayer mode and return to main menu
      if (playerId == localPlayerId && multiplayerManager != null &&
  multiplayerManager.IsMultiplayerMode)
      {
          Debug.Log($"LobbyUIManager: Local player {playerId} left the lobby
   (kicked or disconnected). Returning to main menu.");
          multiplayerManager.DisableMultiplayerMode();
          PPSceneManager.LoadMainMenu();
      }
  }

  Key logic:
  - Checks if the leaving player is the local player (playerId == 
  localPlayerId)
  - Verifies multiplayer mode is still active
  (multiplayerManager.IsMultiplayerMode) to avoid duplicate scene loads
  - Calls DisableMultiplayerMode() to clean up Firebase listeners and reset
  state
  - Loads the main menu via PPSceneManager.LoadMainMenu()

  2. Updated OnLeaveLobbyClicked() (lines 584-592)

  Also fixed the existing leave button handler to properly transition to the
   main menu:
  public void OnLeaveLobbyClicked()
  {
      // This would be attached to a Leave Lobby button in the UI
      if (multiplayerManager != null)
      {
          multiplayerManager.DisableMultiplayerMode();
          PPSceneManager.LoadMainMenu();

  }

  3. Already Implemented KickPlayer() in LobbyManager.cs (lines 411-461)

  The kick functionality from the previous task remains intact and now works

  How It Works

  1. Host kicks a player → LobbyManager.KickPlayer() removes player from
  Firebase
  2. Firebase event → OnPlayerRemoved triggers in all clients (including
  kicked player)
  3. MultiplayerManager → RemovePlayerFromFirebase() calls OnPlayerLeft
  event
  4. Kicked player's UI → OnPlayerLeft() detects playerId == localPlayerId
  and:
    - Disables multiplayer mode (cleans up Firebase listeners)
    - Loads the main menu scene
  5. Other players → OnPlayerLeft() updates UI but doesn't trigger scene
  change

  Safety Features

  - Prevents double scene loads: Checks IsMultiplayerMode before
  transitioning
  - Clean shutdown: Calls DisableMultiplayerMode() before scene change
  - Host protection: Only triggers for the kicked player (not the host or
  other players)
  - Voluntary leave handling: OnLeaveLobbyClicked() now also loads main menu

  Optional Enhancement

  Host leaving scenario: Currently not handled. If the host leaves
  voluntarily, other players remain in the lobby but cannot start the game.
  This could be addressed by adding a check in OnPlayerLeft() for when the
  leaving player is the host, then forcing all remaining players back to the
   main menu.
