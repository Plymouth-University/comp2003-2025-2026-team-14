● The SpectatorPanel wasn't appearing due to a Start() method timing issue.
  Here's the root cause and what I fixed:

  Root Cause

  The SpectatorUIManager.Awake() hides the panel (SetActive(false)). Then
  GameManager.Start() calls spectatorUI.OnSpectatorDataReady() to show it.
  The problem is that OnSpectatorDataReady() checks for the cached
  spectatorManager field, which is only assigned in
  SpectatorUIManager.Start(). If GameManager.Start() runs before
  SpectatorUIManager.Start(), spectatorManager is null, opponentPlayerIds is
   null → NullReferenceException on .Count > 0 → method crashes → panel
  never gets shown.

  Changes Made

  SpectatorUIManager.cs — Two fixes:

  1. Line 32: Initialized opponentPlayerIds with new List<string>() instead
  of leaving it null
  2. Lines 81-101: OnSpectatorDataReady() now uses SpectatorManager.Instance
   as a fallback if the cached spectatorManager field isn't set yet:
  var specManager = spectatorManager ?? SpectatorManager.Instance;

  developer-instructions.md — Added:
  - Step 4: Script Execution Order setup instructions (recommended)
  - Known Limitations #6: Documents the Start() timing issue
  - Section 7: Script execution order preference explanation

  The panel should now appear when multiplayer game starts. You should also
  configure Script Execution Order (Edit > Project Settings > Script 
  Execution Order) to set SpectatorUIManager earlier than GameManager for
  the cleanest behavior.
