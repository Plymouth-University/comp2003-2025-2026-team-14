● I've analyzed the logic and added comprehensive debugging to trace why
  OnPlayerLeft isn't being called for kicked players. The issue appears to
  be in the event propagation chain from Firebase removal to the UI scene
  transition.

  Key Changes Made

  1. Enhanced Debug Logging

  - LobbyUIManager.OnPlayerLeft: Added try-catch block with detailed logging
   of localPlayerId retrieval and comparison logic
  - MultiplayerManager.RemovePlayerFromFirebase: Added explicit invocation
  logging with exception handling
  - LobbyUIManager event subscription: Added specific logs for OnPlayerLeft
  subscription/unsubscription
  - All methods now log: Every step in the chain now logs its execution
  state

  2. Critical Fix in RemovePlayerFromFirebase

  The key issue was in the condition for invoking OnPlayerLeft. Previously
  it required:
  if (isLocalPlayer || wasInPlayers) { ... }

  When a player is kicked:
  - wasInPlayers might be false if the player was already removed from the
  local dictionary
  - isLocalPlayer should be true but depends on LocalPlayerId being
  correctly set

  The enhanced logic now:
  - Logs both conditions explicitly
  - Invokes within try-catch to catch any subscriber exceptions
  - Added detailed logging before/after invocation

  3. Event Subscription Tracking

  Added specific logs to:
  - SubscribeToEvents(): Logs when OnPlayerLeft is subscribed
  - UnsubscribeFromEvents(): Logs when OnPlayerLeft is unsubscribed
  - Shows subscriber counts before/after each operation

  Debugging Chain

  When a player is kicked, the expected flow is:
  1. Host calls LobbyManager.KickPlayer() → Firebase RemoveValueAsync()
  2. Firebase updates → All clients receive OnPlayerRemoved event
  3. LobbyManager.OnPlayerRemoved → Calls
  MultiplayerManager.RemovePlayerFromFirebase
  4. RemovePlayerFromFirebase → Invokes OnPlayerLeft event
  5. LobbyUIManager.OnPlayerLeft → Detects local player → LoadMainMenu()

  Critical Points to Check in Logs

  When testing, look for these logs in order:

  1. LobbyManager.OnPlayerRemoved: Is this player being removed the local 
  player? - Determines if the kicked player recognizes themselves
  2. MultiplayerManager: wasInPlayers={...}, isLocalPlayer={...}, 
  LocalPlayerId={...} - Shows the comparison logic
  3. MultiplayerManager: OnPlayerLeft subscriber count: ... - Should be >0
  if LobbyUIManager is subscribed
  4. MultiplayerManager: INVOKING OnPlayerLeft for player ... - Confirms
  event is being invoked
  5. LobbyUIManager: OnPlayerLeft called with playerId=... - Confirms
  handler is being called

  Common Failure Points

  1. Event not subscribed: If subscriber count is 0, check LobbyUIManager
  lifecycle (is GameObject active?).
  2. LocalPlayerId mismatch: If isLocalPlayer is false, the ID comparison is
   failing.
  3. Exception in handler: The try-catch will catch and log any exceptions
  in OnPlayerLeft.
  4. Scene transition timing: LoadMainMenu() might be interrupting the
  logging output.

  Next Steps

  1. Test with the new logging and share which logs appear/are missing
  2. Check Unity Console for any error messages
  3. Verify Firebase authentication: Ensure LocalPlayerId is properly set
  from FirebaseManager.UserId

  The enhanced logging should pinpoint exactly where the chain breaks -
  whether it's in the Firebase event propagation, the local player
  identification, event subscription, or the scene transition itself.
