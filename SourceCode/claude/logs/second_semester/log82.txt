  Diagnosis

  After tracing through the spectator mode switch/restore cycle, I've
  identified the root cause:

  ShapeManager.ClearAllShapes() destroys shape GameObjects via Destroy() but
   never nulls out tile.occupyingShape on GridTiles.

  Here's the problematic sequence:

  1. Player switches to spectator (opponent) → opponent shapes are created,
  FinalizePlacement() sets tile.occupyingShape on grid tiles
  2. Player switches back → ClearAllShapes() destroys opponent GameObjects →
   but tile.occupyingShape still holds references to those destroyed
  ShapeController objects
  3. RestoreLocalPlayerBoard() creates new shapes and calls
  FinalizePlacement() → correctly overwrites tile.occupyingShape for local
  player's tiles
  4. BUT: for tiles the opponent occupied that the local player does NOT,
  tile.occupyingShape still points to destroyed objects

  In Unity, != null on a destroyed MonoBehaviour should return false via
  Unity's operator overload, but in practice there can be edge cases with
  this — particularly when references are accessed through collections or
  between frames. If IsOccupied() incorrectly returns true for even a few
  tiles that should be empty, it can cascade: the auto-end detector's
  GetAllEmptyNonRiverPositions() returns fewer positions,
  IsAdjacentToExistingBuilding() fails, and the detector incorrectly
  concludes no valid placements exist.

  The fix is to explicitly null out tile.occupyingShape on all grid tiles in
   ClearAllShapes().

● Summary

  Root Cause

  The bug is in ShapeManager.ClearAllShapes()
  (Assets/Scripts/ShapeManager.cs:623). It destroys shape GameObjects via
  Destroy() but never nulls out tile.occupyingShape on GridTiles. This
  leaves dangling references to destroyed MonoBehaviour objects on the grid.

  How it manifests

  1. You spectate an opponent → their shapes are created and
  FinalizePlacement() sets tile.occupyingShape on all the tiles their shapes
   cover.
  2. You switch back to local → ClearAllShapes() calls Destroy() on opponent
   GameObjects, but tile.occupyingShape still points to those destroyed 
  objects.
  3. RestoreLocalPlayerBoard() creates new local shapes →
  FinalizePlacement() correctly overwrites tile.occupyingShape for tiles the
   local player occupies.
  4. However, for tiles the opponent occupied but the local player does NOT,
   tile.occupyingShape still references the destroyed opponent
  ShapeController.

  When the auto-end detector runs AllEmptyNonRiverPositions() → IsOccupied()
   → tile.occupyingShape != null, Unity's overloaded null-check for
  destroyed objects can behave inconsistently, causing tiles to be
  incorrectly reported as occupied. This cascades: fewer empty positions are
   available, adjacency checks fail, and the detector concludes no valid
  placements exist.

  Fix

  Added an explicit pass in ClearAllShapes() to null out tile.occupyingShape
   and tile.zone on every grid tile after destroying shapes:

  for (int x = 0; x < 10; x++)
  {
      for (int y = 0; y < 10; y++)
      {
          GridTile tile = TilemapManager.Instance.gridTiles[x, y];
          if (tile != null)
          {
              tile.occupyingShape = null;
              tile.zone = null;
          }
      }
  }

  This ensures the grid is in a clean state before shapes are restored via
  PlaceShapesFromBoardState() / FinalizePlacement(). The auto-end detector
  will then correctly see only the local player's shapes as occupying tiles.
