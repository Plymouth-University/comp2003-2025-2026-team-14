● Now I have a clear picture of the issue. Let me summarize what's happening
   and present the fix options.

  The Problem

  The timing chain is:

  1. Player taps the "Confirm" button (which overlaps a starting position
  tile underneath)
  2. GameManager.OnTouchPress() fires first (Input System callback) → sees
  firstTurnCompleted == false → calls HandleStartingPositionSelection() →
  changes selectedStartingPosition → placement rules update → confirm button
   gets disabled
  3. Then ManipulationUIManager.OnConfirmButtonClicked() fires (Unity UI
  Button.onClick) → calls shapeManager.activeShape.OnShapeConfirm() → but by
   now the placement is invalid because the starting position changed

  The root cause is that OnTouchPress is an Input System callback that fires
   independently of Unity's UI EventSystem, so touches on UI elements can
  fall through to the grid interaction logic.

  Fix Options

  Option A — Check if an active shape exists (game state check):

  In GameManager.OnTouchPress(), add a guard at the very top:

  // Don't process starting position selection if a shape is already being 
  placed
  if (shapeManager != null && shapeManager.activeShape != null)
      return;

  This works because: starting position selection happens before any shape
  is created. Once activeShape exists, the starting position has already
  been chosen. So we can safely skip HandleStartingPositionSelection during
  the entire shape placement phase.

  Option B — Check if the touch is over a UI element:

  if (EventSystem.current != null &&
  EventSystem.current.IsPointerOverGameObject())
      return;

  This is the standard Unity pattern for preventing UI clicks from falling
  through to game-world interaction. However, the timing is less reliable —
  if the Input System callback fires before the EventSystem processes the
  pointer, IsPointerOverGameObject() could return a stale value from the
  previous frame.

  My recommendation is Option A. It's simpler, relies on existing game state
   (no dependency on event ordering), and is semantically correct: starting
  position selection should only be possible when no shape is being placed.

  What do you think?
