       178 +  ### Multiplayer State Management Across Scenes
       179 +  
       180 +  The multiplayer system maintains state across scene 
           + transitions using a combination of Firebase Realtime 
           + Database and local singleton managers:
       181 +  
       182 +  #### 1. **Persistent Manager Singletons** 
           + (`DontDestroyOnLoad`)
       183 +  - `PPSceneManager`: Handles scene transitions, persists 
           + across all scenes
       184 +  - `FirebaseManager`: Maintains Firebase connection and 
           + authentication state
       185 +  - `MultiplayerManager`: Coordinates multiplayer gameplay, 
           + tracks lobby/game state
       186 +  - `LobbyManager`: Manages lobby-specific data (player list,
           +  ready states)
       187 +  
       188 +  #### 2. **Firebase Database as Source of Truth**
       189 +  - **Lobby State**: Stored in `lobbies/{lobbyCode}` with 
           + player list, ready states
       190 +  - **Game State**: Stored in `games/{lobbyCode}` with turn 
           + number, dice rolls, player placements
       191 +  - **Scene-Independent**: Firebase data persists regardless 
           + of which scene players are in
       192 +  
       193 +  #### 3. **Scene Transition Flow with State Preservation**
       194 +  - **Join Lobby Scene** → **Lobby Scene**:
       195 +    - Player enters lobby code, `LobbyManager` joins Firebase
           +  lobby
       196 +    - `MultiplayerManager` stores `currentLobbyCode` and 
           + player data
       197 +    - Scene transition via `PPSceneManager.LoadLobby()`
       198 +    - `LobbyManager` listens to Firebase 
           + `lobbies/{lobbyCode}` for player list updates
       199 +  
       200 +  - **Lobby Scene** → **Game Scene**:
       201 +    - Host starts game, writes `gameStarted: true` to 
           + Firebase
       202 +    - All clients detect change, `MultiplayerManager` 
           + switches to game mode
       203 +    - Scene transition via `PPSceneManager.LoadMainGame()`
       204 +    - `MultiplayerManager` initializes game with synchronized
           +  seed from Firebase
       205 +  
       206 +  - **Game Scene** → **End Game Scene**:
       207 +    - Game end detected, final scores calculated
       208 +    - Scene transition via `PPSceneManager.LoadResults()`
       209 +    - `MultiplayerManager` retains game results for display
       210 +  
       211 +  #### 4. **Reconnection & Scene Recovery**
       212 +  - If player disconnects/reconnects or switches scenes:
       213 +    - `FirebaseManager` re-establishes connection
       214 +    - `MultiplayerManager` checks `currentLobbyCode` and 
           + rejoins Firebase listeners
       215 +    - UI updates based on latest Firebase data
       216 +    - Player can rejoin ongoing game from any scene
       217 +  
       218 +  #### 5. **Local State vs Firebase State**
       219 +  - **Local State**: Player's board, selected dice, shape 
           + ghost (not synced until confirmed)
       220 +  - **Firebase State**: Confirmed placements, dice rolls, 
           + turn number, player scores
       221 +  - **Synchronization**: `SyncManager` broadcasts local 
           + actions to Firebase, listens for others' actions
       222 +  
       223 +  #### 6. **Implementation with Existing PPSceneManager**
       224 +  The existing `PPSceneManager` singleton provides scene 
           + transition methods that preserve multiplayer state:
       225 +  ```csharp
       226 +  // Example flow:
       227 +  PPSceneManager.Instance.LoadLobby(); // Keeps 
           + FirebaseManager, MultiplayerManager alive
       228 +  // LobbyScene UI uses LobbyManager to display player list 
           + from Firebase
       229 +  ```
